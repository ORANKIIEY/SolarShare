# Sample asset documents (SAMPLE: NOT REAL DOCUMENTS)

These PDFs show the kind of paperwork that proves who legally owns the Block A
solar mini-grid and how it earns money. **They are samples made for the
SolarShare hackathon demo.** Every page carries a large "SAMPLE: NOT A REAL
DOCUMENT" watermark. All people, companies, registration numbers, serial
numbers and addresses are fictional. They were not issued by any registry,
installer or authority.

| File | Onchain name | What it would prove |
| --- | --- | --- |
| [`spv-company-certificate.pdf`](spv-company-certificate.pdf) | `SPV_CERTIFICATE` | The company "Solar Share Block A SPV (Pty) Ltd" exists, owns only this mini-grid, and has 3,500 shares (the tokens). |
| [`installation-certificate.pdf`](installation-certificate.pdf) | `INSTALLATION_CERTIFICATE` | The 10 kWp solar + 20 kWh battery system was installed and tested, and which meter reports its output. |
| [`power-purchase-agreement.pdf`](power-purchase-agreement.pdf) | `POWER_PURCHASE_AGREEMENT` | 20 homes and 5 spaza shops buy the electricity at 0.20 per kWh: the income that pays shareholders. |

## How the hashes prove the documents weren't swapped

[`hashes.json`](hashes.json) lists each file's SHA-256 hash (a fingerprint:
change one byte and it's completely different). The deploy script writes these
hashes into the `SolarShareToken` contract on Base Sepolia
(`getDocuments()`). Anyone can download a file, hash it, and compare. The web
app's **Verify** button does exactly that in the browser
(`Blockchain/interface/README.md`, "Verify a document").

To check by hand:

```bash
sha256sum spv-company-certificate.pdf        # Linux / Git Bash
shasum -a 256 spv-company-certificate.pdf    # macOS
```

```powershell
Get-FileHash spv-company-certificate.pdf -Algorithm SHA256   # Windows
```

## Where the files live

For now each onchain link is the file's GitHub raw URL on `main`
(`https://raw.githubusercontent.com/ORANKIIEY/SolarShare/main/docs/asset-documents/<file>`).
**Production would pin them to IPFS** instead: an IPFS address is derived from
the file's content, so the link itself can never point at a different file.

## Rebuild

The PDFs are generated by `Blockchain/scripts/build-asset-documents.ts`
(pdfkit). From `Blockchain/`:

```bash
npm run docs:build
```

The build is deterministic: the same text always gives byte-identical files
and the same hashes. If you change the text, the hashes change too, and the
onchain hashes must be updated (`SolarShareToken.setDocument`) or the Verify
check will (correctly) fail.
